# FLOW AI — Frontend ↔ Backend Integration Mapping

> Generated by inspecting the frontend source (`src/data/simulatedData.js`, components,
> pages) and by capturing **live responses** from the running Flask backend
> (`http://localhost:5000`, seed state). No field name in this document is guessed:
> backend fields were read from actual HTTP responses; frontend fields were read from
> the actual components that render them.
>
> **Status: not integrated yet.** The API helpers exist (`src/api/`), but no page has
> been switched over to them — every page still renders the demo dataset.

---

## 1. Envelope (both sides)

Backend success: `{ "ok": true, "data": <payload>, "meta": { "simulated": true, "api_version": "1.0", "notice": "…" } }`
Backend failure: `{ "ok": false, "error": { "code": "<code>", "message": "…" }, "meta": { … } }`

Failure codes observed live: `validation_error` (400), `not_found` (404), `invalid_transition` (409),
`method_not_allowed` (405). The client (`src/api/client.js`) unwraps `data` and converts every
failure into a typed `ApiError` (`kind`: network | timeout | http | invalid-json | invalid-response | server).

Frontend has no envelope concept — its demo data is bare arrays/objects. The helpers bridge this.

## 3. Exact backend payloads (captured live)

### GET /api/health → `data`
`status, service, api_version, notice, simulation: { clock, step, running }`

### GET /api/dashboard → `data`
```
summary:        { roads_monitored, avg_congestion, avg_speed_kmh,
                  active_incidents, active_missions, vehicles_observed }
incidents:      { total, active, resolved, dismissed,
                  by_severity: { critical, high, medium, low },
                  by_type: { accident, breakdown, construction, flooding,
                             police_activity, signal_failure } }
emergency:      { total, active,
                  by_status: { requested, enroute, completed, cancelled },
                  by_unit_type: { ambulance, fire, police } }
congestion_breakdown: { smooth, moderate, congested, gridlock }
busiest_roads:       [ { road_id, name, congestion, status } ]
highest_risk_roads:  [ { road_id, predicted_status, risk_score } ]
simulation:     { clock, step }
notice:         string
```

### GET /api/roads → `data`
`count`, `roads[]` each: `id, name, category, from { name, lat, lng }, to { name, lat, lng },
length_km, congestion (0–100 float), status ('smooth'|'moderate'|'congested'|'gridlock'),
avg_speed_kmh, free_flow_speed_kmh, vehicle_count, simulated`

### GET /api/incidents → `data`
`count`, `incidents[]` each: `id, road_id, type, severity, status, description,
location { lat, lng }, reported_at ('HH:MM:SS'), simulated`
- `type` ∈ accident | breakdown | construction | flooding | police_activity | signal_failure
- `severity` ∈ critical | high | medium | low  ← **matches frontend**
- `status` ∈ active | in_progress | resolved | dismissed

### GET /api/predictions → `data`
`count, horizon_minutes, method ('deterministic_heuristic'), model_trained (false), predictions[]`
each: `road_id, road_name, current_congestion, predicted_congestion, delta_congestion,
predicted_status, category, risk_score, trend, factors[], recommendation, confidence,
horizon_minutes, method, simulated`

### GET /api/emergency/missions → `data`
`count`, `missions[]` each: `id, origin { lat, lng }, origin_road_id, destination { lat, lng },
destination_road_id, unit_type, priority (int 1–5), status, notes, requested_at, simulated, route`
`route`: `origin_junction, destination_junction, road_ids[], segments[] { type, road_id?, from, to,
distance_km, travel_time_min, congestion }, distance_km, travel_time_min, raw_travel_time_min,
free_flow_time_min, priority_time_saved_min, congestion_exposure, cost, priority, reachable,
simulated_intersection_priority, disclaimer, estimates { delay_min, excess_fuel_l, excess_co2_kg, note }`
- `unit_type` ∈ ambulance | fire | police  ← **matches frontend `type`**
- `status` ∈ requested | enroute | completed | cancelled

### GET /api/impact → `data`
```
network: { road_count, delay_vehicle_hours, fuel_liters, co2_kg,
           roads[] { road_id, name, congestion, vehicle_count,
                     delay_vehicle_hours, fuel_liters, co2_kg } }
missions: { routes_estimated, routes_unreachable, delay_minutes_total,
            excess_fuel_liters_total, excess_co2_kg_total,
            missions[] { mission_id, unit_type, priority, reachable,
                         distance_km, delay_min, excess_fuel_l, excess_co2_kg } }
assumptions: string[]   units: { time, fuel, emissions }
simulation: { clock, step }   notice: string
```

## 4. Gaps — where frontend expectations do NOT match backend data

These require an **adapter layer** (not yet written) or a UI decision; they are the reason the
frontend is not switched over yet:

| # | Frontend expects | Backend provides | Needed |
|---|---|---|---|
| 1 | road `congestion` level string `free/moderate/heavy/severe` | numeric `congestion` + `status smooth/moderate/congested/gridlock` | map: smooth→free, moderate→moderate, congested→heavy, gridlock→severe |
| 2 | road single `lat`/`lng` point | `from`/`to` endpoint pairs | midpoint of from/to for the marker |
| 3 | road `volume` veh/h, `note` | `vehicle_count`, no note | vehicle_count ≈ volume; note derived (e.g. category) or omitted |
| 4 | incident `title`, `road` (name), `minutesAgo` | `type`+`description`, `road_id`, `reported_at` + sim clock | derive title from type/description; resolve road_id→name via `/api/roads`; minutesAgo = clock − reported_at |
| 5 | incident `status open/acknowledged` | `active/in_progress/…` | open→active, acknowledged→in_progress; **UI actions must call PATCH**, not local state |
| 6 | incident `lanes`, `owner`, `source` | none | leave blank / drop column |
| 7 | mission `unit`, `task`, `from`/`to` labels, `corridor`, `progress`, `junctionsCleared/Total`, `etaMin` | `notes`, `origin/destination` coords, `route.*` | task←notes; from/to←route.origin_junction/destination_junction; etaMin←route.travel_time_min; corridor←road_ids joined; **progress and junctions counts have no backend source** (derive from status or drop) |
| 8 | mission `priority` string critical/high/medium | int 1–5 | map 1→critical, 2→high, 3+→medium/low (UI styles only cover critical/high/medium) |
| 9 | mission `status en-route/dispatched/on-scene` | requested/enroute/completed/cancelled | requested→dispatched, enroute→en-route; `cancelled` has **no statusMeta chip** (falls back to default) |
| 10 | 6 fixed KPI cards with `value/delta/hint` strings | `dashboard.summary` numbers | build KPI strings client-side; several demo KPIs (CO₂ saved today, +3 roads) have no backend metric |
| 11 | impact `summary/weekly/hourlySavings/breakdown` | single-step `network` totals + mission totals | weekly/hourly/breakdown series have **no backend source** — must stay demo or be derived across steps |
| 12 | chart series (24 h flow, 7 d trend, congested/hour) | none (only current snapshot) | stay demo-labelled until backend adds series |
| 13 | predictions UI | full `/api/predictions` data | **new UI needed** (helpers ready, nothing renders predictions yet) |
| 14 | map centre Bengaluru `12.9716, 77.5946` | Hyderabad network `≈17.3–17.5, 78.3–78.6` | `MAP_CENTER` must move when backend roads are used |
| 15 | incident/mission id style `INC-1042`/`MSN-207` | `inc-0001`/`emg-0001` | cosmetic; either accept backend ids or reformat in adapter |

## 5. Files created (this task)

| file | purpose |
|---|---|
| `src/api/client.js` | fetch wrapper: `VITE_API_BASE_URL` (default `http://localhost:5000`), typed `ApiError` for network/timeout/HTTP/invalid-JSON/invalid-shape failures, envelope unwrapping, `expectPayload` shape checks |
| `src/api/endpoints.js` | one helper per endpoint: `getHealth, getDashboard, getRoads, getIncidents, getPredictions, getMissions, getImpact`, `predict, calculateRoute`, mutations `createIncident, updateIncident, createMission, updateMission, stepSimulation, resetSimulation`, plus `loadWithFallback` (read-only, labels demo data) |
| `src/api/useApiResource.js` | hook returning `status: loading/ready/error/empty`, `source: 'backend' | 'demo'`, `isFallback`, `fallbackNotice`, `retry` |
| `INTEGRATION_MAPPING.md` | this document |

Config: `.env` / `.env.local` may define `VITE_API_BASE_URL`; absent it defaults to `http://localhost:5000`.

Rules enforced by the helpers:
- Mutations **throw** `ApiError` on any failure — no fallback path exists for them, so a failed
  backend mutation can never be presented as successful.
- Demo fallback (`loadWithFallback` / `useApiResource({ fallback })`) is read-only and returns
  `source: 'demo'` + `DEMO_FALLBACK_NOTICE` so the UI must label it.
